# Movie Finder 개발 계획

PRD(`docs/PRD.md`) 기준으로 기능을 구현한다.  
프로젝트 생성, conda 환경(`movie`), FastAPI/React scaffold, CORS·SQLite·`/health` 연결은 **이미 완료**된 상태로 보고, 아래 단계는 **기능 구현부터** 진행한다.

---

## 0. 현재 기준점 (이미 준비됨)

| 영역 | 상태 |
|------|------|
| `backend/` | FastAPI + CORS + SQLite(`app.db`) + `/health` |
| `frontend/` | Vite React + `api.js`의 `checkHealth` + 연결 확인 화면 |
| 환경 | conda `movie`, `requirements.txt` / `package.json` 구성 완료 |
| 문서 | `docs/PRD.md` 기준 |

이후 작업은 이 뼈대 위에 **도메인 모델 → 공공데이터 연동 → REST API → React 화면** 순으로 얹는다.

프론트엔드는 공공데이터를 직접 호출하지 않고, **FastAPI만** 호출한다.

```
공공데이터 API → FastAPI → SQLite 저장/조회 → React
```

---

## 1. MVP 개발 순서

MVP 목표: 박스오피스 Top 10 확인, 제목/감독/개봉일 검색, 상세 정보 팝업.

### Phase 1 — 백엔드 기반 (모델 · 설정 · 클라이언트)

1. **환경 변수·설정**
   - `backend/.env`에 공공데이터 API 키·베이스 URL 등 설정
   - `python-dotenv`로 로드

2. **SQLite 데이터 모델 (SQLModel)**
   - 박스오피스 일별 순위
   - 영화 기본/검색용 정보
   - 영화 상세 정보(감독·배우·상영·심의·영화사·스태프 등)

3. **공공데이터 API 클라이언트**
   - 일별 박스오피스 조회
   - 영화 목록 검색(제목·감독·개봉일)
   - 영화 상세 조회
   - 응답을 내부 스키마로 변환

4. **캐시/저장 전략**
   - 조회 결과를 SQLite에 저장
   - 동일 조건 재요청 시 DB 우선 조회 후, 필요 시 외부 API 호출

### Phase 2 — 백엔드 REST API (MVP)

5. **박스오피스 API**
   - 오늘의(또는 기준일의) Top 10 반환
   - 순위, 영화코드, 제목, 감독, 포스터 URL(가능 시) 포함
   - DB 저장 후 응답

6. **영화 검색 API**
   - 쿼리: 제목 / 감독명 / 개봉일 (조합 가능 여부는 공공 API 제약에 맞춤)
   - 검색 결과 필드: 국·영문 제목, 제작연도, 개봉일, 유형, 장르, 감독, 제작사 등
   - 결과를 DB에 반영

7. **영화 상세 API**
   - 영화코드 기준 상세 조회
   - PRD 상세 필드(기본·감독·배우·상영·심의·영화사·스태프) 제공
   - 상세도 SQLite에 캐시

8. **에러·빈 결과 처리**
   - 외부 API 실패, 키 미설정, 결과 없음에 대한 일관된 응답

### Phase 3 — 프론트엔드 공통 · 소개

9. **API 클라이언트 확장**
   - `frontend/src/api.js`에 박스오피스·검색·상세 호출 함수 추가
   - 로딩/에러 상태를 화면에서 다루기 쉽게 정리

10. **앱 레이아웃·라우팅(또는 섹션 구성)**
    - 소개 / 박스오피스 / 검색이 한 앱에서 자연스럽게 이어지도록 구성
    - (필요 시) 간단한 페이지 전환

11. **소개 화면**
    - 서비스 소개, 주요 기능, 검색 사용 방법

### Phase 4 — 박스오피스 UI

12. **박스오피스 Top 10 조회 연동**
    - 마운트 시 백엔드 API 호출
    - 로딩·에러·빈 목록 UI

13. **캐러셀 (Swiper 등)**
    - Desktop 5 / Tablet 3 / Mobile 1
    - 자동 슬라이드(기본 2초, 1~2초 설정 가능)
    - 무한 루프, 좌우 버튼, hover 시 일시정지
    - 전환 애니메이션 300~500ms
    - 카드: 순위, 포스터, 제목, 감독

14. **카드 클릭 → 상세 팝업 연결**
    - 영화코드로 상세 API 호출 후 모달 표시

### Phase 5 — 검색 · 결과 · 상세 팝업

15. **검색 폼**
    - 영화 제목, 감독 이름, 개봉일 입력
    - 검색 버튼 / 제출

16. **검색 결과 목록**
    - PRD 결과 필드 표시
    - 행/카드 클릭 시 상세 팝업
    - 팝업을 닫아도 검색 목록 유지

17. **영화 상세 정보 모달**
    - 기본·감독·배우·상영·심의·영화사·스태프 섹션
    - 닫기(X), 외부 클릭, ESC, 내부 스크롤

### Phase 6 — MVP 마무리

18. **통합 점검**
    - PRD MVP 완료 기준 체크
    - 반응형·캐러셀 성능(초기 로딩 목표 1초 이내) 확인
    - API·화면 오류 메시지 정리

## 4. 의존성·구현 시 참고

- **백엔드**: 기존 `sqlmodel`, `requests`, `python-dotenv` 활용. 공공 API 스펙(키·엔드포인트)은 별도 제공 예정 정보를 `.env`와 클라이언트에 반영.
- **프론트**: 캐러셀은 PRD 권장대로 Swiper 등 도입. 즐겨찾기는 서버 없이 `localStorage`.
- **제외**: 로그인, 회원가입, 리뷰, 별점, 결제, 관리자, 알림, Leaflet 지도(MVP 미사용).
